**前置文档：** 01～08
**适用对象：** 产品负责人、UI/UX、前端开发、后端开发、测试、门店培训人员

---

# 一、前端设计目标

V1前端设计目标不是：

> “比旧系统好看。”
> 
> 

而是：

> **比旧系统更容易维护，同时让门店员工能够快速完成原有操作。**
> 
> 

核心原则：

```Plain Text
业务正确
   ↓
操作简单
   ↓
响应快速
   ↓
状态明确
   ↓
错误可恢复
   ↓
权限可控
```

---

# 八、前端权限显示原则

页面层：

> 没权限就不展示。
> 
> 

按钮层：

> 没权限就不展示。
> 
> 

API层：

> 即使前端隐藏，后端仍必须重新校验。
> 
> 

前端权限只是用户体验。

后端权限才是最终安全边界。

# 二十三、耗卡来源选择器

> 
>

```Plain Text

```

---

当选择赠金：

```Plain Text
赠金余额：¥1,200

```

---

当选择混合：

```Plain Text
本金：¥100
赠金：¥200
合计：¥300
```

输入金额时必须实时校验：

```Plain Text
本金使用 ≤ 本金余额
赠金使用 ≤ 赠金余额
本金+赠金 = 消耗金额
```

# 六十四、前端页面与API关系

原则：

> 一个页面可以调用多个查询API，但核心业务动作尽量一个业务API完成。
> 
> 

例如耗卡：

```Plain Text

 ↓
GET customer
GET customer/assets
GET projects
```

点击：

```Plain Text
完成消耗
```

只调用：

```Plain Text
POST /treat/orders/{id}/complete
```

而不是前端自己调用：

```Plain Text
扣卡
完成服务
生成客流
生成业绩
扣库存
```
