# Cursor 前端页面验收 Prompt

## 一、Prompt定位

你现在承担：

> **ERP业务验收工程师**

目标：

从真实业务人员的使用角度，验证当前页面：

```text
能不能用
+
能不能正确操作
+
权限是否正确
+
业务规则是否正确
+
异常是否正确
```

---

# 二、验收原则

> **不是“页面能打开”就算完成。**

必须验证：

```text
进入
↓
查询
↓
操作
↓
提交
↓
成功
↓
失败
↓
权限
↓
异常
↓
刷新
↓
门店切换
```

---

# 三、验收前必须检查

```text
04 页面设计
05 页面代码
07 API联调
08 代码审查
09 业务规则审查
```

如果 08 或 09 未通过：

> 不得直接 PASS。

---

# 四、基础验收

## 1. 页面访问

检查：

```text
路由是否正确
是否需要登录
无权限是否正确
404是否正确
```

---

# 五、加载验收

检查：

```text
首次加载
Loading
接口成功
空数据
接口失败
网络异常
```

---

# 六、查询验收

检查：

```text
输入条件
查询
重置
分页
刷新
```

重点：

> 查询条件与 API 参数必须对应。

---

# 七、表单验收

检查：

```text
必填
格式
长度
金额
数字
日期
枚举
```

非法数据不能提交。

---

# 八、权限验收

至少验证：

```text
有权限
无权限
不同角色
不同门店
```

检查：

```text
菜单
路由
按钮
操作
```

---

# 九、门店验收

如果页面涉及门店：

```text
门店A
↓
查看数据
↓
切换门店B
↓
重新加载
↓
检查数据是否已经切换
```

必须确保：

> 不存在 A 门店数据残留。

---

# 十、操作验收

例如客户：

```text
新增
编辑
查看
删除
停用
启用
```

销售：

```text
选客户
选项目
选择渠道
设置经手人
支付
提交
```

预约：

```text
新增
修改
确认
取消
到店
爽约
```

---

# 十一、重复操作

重点测试：

```text
连续点击提交
连续点击支付
连续点击退款
连续点击开单
```

不能产生重复业务数据。

---

# 十二、异常验收

必须测试：

```text
10001
10002
10003
50000
网络断开
接口超时
后端业务校验失败
```

检查前端是否正确处理。

---

# 十三、页面刷新

检查：

```text
F5
重新进入
浏览器后退
浏览器前进
```

确认：

```text
Token
用户
权限
当前门店
页面状态
```

符合设计。

---

# 十四、验收结果

使用：

```text
PASS
通过

FAIL
存在问题

BLOCKED
无法继续，因为依赖未完成
```

---

P2

P3
