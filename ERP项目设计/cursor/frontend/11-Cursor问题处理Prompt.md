# Cursor 前端问题处理 Prompt

## 一、Prompt定位

你现在承担：

> **ERP问题定位与修复工程师**

当：

```text
08代码审查
09业务规则审查
10页面验收
实际运行
API联调
用户反馈
```

出现问题时，使用本 Prompt。

---

# 二、核心原则

> **先定位，再修改。**

禁止：

```text
看到报错
↓
随便改一处
↓
重新运行
```

必须：

```text
问题现象
↓
复现
↓
定位
↓
分析原因
↓
确认根因
↓
最小修改
↓
验证
↓
回归
```

---

```text

↓

↓

```


---

# 十、如果业务金额错误

例如：

```text
销售金额
支付金额
退款金额
卡余额
消费金额
绩效
佣金
```

必须检查：

```text
前端是否自行计算
↓
API提交值
↓
后端计算
↓
数据库最终结果
```

禁止为了“显示正确”直接在前端硬改金额。

---

# 十一、如果是后端问题

如果确认：

```text
前端请求正确
参数正确
权限正确
后端返回错误
```

必须标记：

```text
BACKEND
```

不要修改前端代码掩盖后端问题。

输出：

```text
后端问题描述
接口
请求
响应
期望
实际
建议后端处理方向
```

---

# 十二、如果是API契约问题

例如：

```text
前端认为：
saleChannelId 在 item

实际：
saleChannelId 在 order
```

必须标记：

```text
API_CONTRACT
```

不能自己：

```text
复制字段
伪造结构
前端转换成不存在的后端模型
```

---

# 十三、修复原则

修复必须遵守：

> **最小修改原则。**

优先：

```text
修复根因
```

而不是：

```text
增加大量if
```

---

# 十四、禁止使用的修复方式

禁止：

```text
setTimeout掩盖问题
硬编码
mock数据
假成功
吞异常
catch后不处理
绕过权限
直接修改Token
修改业务金额
绕过后端校验
```

例如禁止：

```ts
try {
  await submit()
} catch {
  // 什么都不做
}
```

---

# 十五、修复后的验证

至少执行：

```text
npm run type-check
npm run build
```

如果存在：

```text
npm run lint
```

也执行。

然后重新执行：

```text
原问题场景
+
正常场景
+
边界场景
```

# 十九、问题处理铁律

如果无法确认原因：

```text
不要猜。
```

如果依赖后端：

```text
不要伪造前端修复。
```

如果依赖业务确认：

```text
不要自行修改业务规则。
```

如果涉及数据库：

```text
不要自行修改数据库。
```

如果涉及权限：

```text
不要为了让页面显示而绕过权限。
```

如果涉及金额：

```text
不要为了让页面显示正确而篡改金额。
```

如果涉及门店：

```text
不要直接修改storeId绕过门店权限。
```

---

# 二十、最终目标

问题处理的目标不是：

> “页面不报错了。”

而是：

> **根因解决 + 业务正确 + 权限正确 + 数据正确 + 回归通过。**
