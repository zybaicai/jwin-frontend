## 1. 领域目标

统一记录「谁、何时、在哪店、对何业务、做了何动作、前后差异、原因」，支撑追溯与权限审计；**不承载**余额、订单状态等业务事实（SYS-003）。

---

## 2. 领域模型（可指导编码）

### 2.1 聚合

| 概念 | 说明 |
|---|---|
| 聚合根 | **无复杂聚合**；`OperationLog` 为追加型实体（append-only） |
| 值对象 | `BizRef(bizType, bizId)`；`JsonSnapshot(text, truncated)` |
| 领域服务 | `OperationLogRules`：必填校验、截断、禁止改删 |

### 2.2 核心属性（对齐 SYS-002）

| 属性 | 说明 |
|---|---|
| id | 主键 |
| operatorId / operatorName | 操作人 |
| storeId | 门店（可空：总部配置类） |
| bizType | 业务对象类型（受控枚举字符串） |
| bizId | 业务主键（字符串，兼容 int/单号） |
| action | 动作（CREATE/UPDATE/APPROVE/…） |
| riskLevel | NORMAL / HIGH（高风险≈原 AuditLog 语义） |
| beforeJson / afterJson | 操作前后快照 |
| reason | 原因（高风险建议必填） |
| ip | 可选 |
| truncated | 是否截断 |
| createdOn | 时间 |

### 2.3 状态机

无状态流转；生命周期 = **INSERT once**。

### 2.4 Application / Repository

| 层 | 职责 |
|---|---|
| `OperationLogApplicationService` | `record(...)`；`page(query)` |
| Repository/Mapper | 仅 insert + select；**不提供 update/delete** |
| 业务 ApplicationService | 在 `@Transactional` 方法内调用 `record` |

### 2.5 与 `*Process` 边界

| 类型 | 例子 | 关系 |
|---|---|---|
| 业务过程事实 | `TB_Refund*Process`、`TB_TreatBillCancelProcess` | 继续写；对账/冲销依据 |
| 操作审计 | `TB_ErpOperationLog` | 跨业务统一查询；可与 Process **双写** |

## 3. 数据库映射（建议，未确认不执行）

### 3.1 分类

| 类 | 对象 | 说明 |
|---|---|---|
| **C** | `TB_ErpOperationLog` | 新建技术支撑表（文档亦称 ERP_OperationLog；命名统一 `TB_Erp*`） |
| A | 各 `*Process` | 完全复用，不改 |
| D | 无 | 不改旧表结构/语义 |

### 3.2 建议表结构（草案）

```text
TB_ErpOperationLog
  ID              bigint IDENTITY 或 int 序列
  OperatorID      nvarchar(50)  NOT NULL
  OperatorName    nvarchar(100) NULL
  StoreID         int           NULL
  BizType         nvarchar(50)  NOT NULL
  BizID           nvarchar(100) NOT NULL
  Action          nvarchar(50)  NOT NULL
  RiskLevel       nvarchar(20)  NOT NULL  -- NORMAL|HIGH
  BeforeJson      nvarchar(max) NULL
  AfterJson       nvarchar(max) NULL
  Reason          nvarchar(500) NULL
  Ip              nvarchar(64)  NULL
  Truncated       bit           NOT NULL DEFAULT 0
  CreatedOn       datetime      NOT NULL
  PK(ID)
  IX (CreatedOn DESC)
  IX (BizType, BizID, CreatedOn)
  IX (StoreID, CreatedOn)
  IX (OperatorID, CreatedOn)
```

## 6. V1 强制埋点清单（对现码）

| BizType（建议） | Action | 埋点位置 | Risk |
|---|---|---|---|
| SALE_CHANNEL_PRICE | UPSERT / DEACTIVATE | `SaleChannelPriceApplicationService` | HIGH |
| SPECIAL_PRICE_APPLY | CREATE/SUBMIT/APPROVE/REJECT/CANCEL/REVOKE | `SpecialPriceApplyApplicationService` | HIGH |
| PRICE_CHANGE_PERMISSION | CREATE/UPDATE/DEACTIVATE/REPLACE_STORES | `PriceChangePermissionApplicationService` | HIGH |
| ACTIVITY | CREATE/UPDATE/DEACTIVATE/REPLACE_PRICES/REPLACE_STORES | `ActivityApplicationService` | HIGH |
| PACKAGE_CARD | CREATE/UPDATE/DEACTIVATE | `PackageCardDefinitionApplicationService` | HIGH |
| REFUND | CREATE/APPROVE/EXECUTE | `RefundApplicationService` | HIGH |
| SAVING_ARREAR_REPAY | REPAY | `SavingCardArrearRepayApplicationService` | HIGH |
| DAY_CLOSE | CLOSE / REOPEN | `PerformanceQueryService.close/reopen` | HIGH（reopen 原因：05 时 API 须带 reason，见缺口） |
| TREAT_ORDER | CANCEL | `TreatApplicationService.cancel` | HIGH（与 CancelProcess 双写） |

### 6.1 明确不进 V1 强制清单（遗留）

| 项 | 原因 |
|---|---|
| 提成规则修改 | `CommissionApplicationService` 仅 calculate/query，无规则写 API |
| 收银改价瞬间 | `PriceChangeApplicationService` 仅 validate；成交改价在销售单快照 |
| 储值充值/消费流水 | 已由销售/耗卡业务事实承载；可选后续补摘要日志 |
| 卡延期/转让 | 若无独立 ERP 写 API 则跳过 |
| `PriceChangeApplicationService.validate` | 只读校验，不记 |

### 6.2 分析缺口（非阻断，05 须处理）

| 缺口 | 建议 |
|---|---|
| `reopen` 当前无 reason 入参 | CONF：解除关账须原因 → 05 给 reopen 增加 `reason`（小改 API，写进文档） |
| IP 获取 | 可选：Filter 写入 Request 属性；无则空 |
