## CONF-001 价格优先级与单店特价

**已确认（按全栈指导书 §十五、原则6～8）：**

```text
单店特殊价格
    >
统一活动价格
    >
区域标准价格
    >
总部基础价格
```

- 门店默认按总部/区域价格销售。  
- **特殊价格必须经总部/区域授权（审批）后才生效。**  
- 临时改价受权限、项目、门店、渠道、金额范围控制。  
- 套餐卡 / 通用次卡 / 时效卡：项目金额来自**卡类商品设计（售卡快照）**，不走普通项目价格匹配。  
- 储值卡消耗：按**当前门店价格区域折扣**动态计算（指导书原则14）。

后续开发以指导书为准，逐步推进，不一次生成整系统。

## CONF-003 次卡退款恢复（锁定）

**已锁定：**

```text
只退「剩余次数」对应部分；
已使用次数不恢复、不退款；
退款金额 = 销售时单次价值快照 × 剩余次数；
不允许按当前项目价重算。
```

整卡未使用时：剩余次数 = 全部次数，可按上式全额退（仍走退款审批）。

（原规则库 CAR-046「暂定」以此条为最终锁定。）

## CONF-007 销售渠道初始字典

**已确认：配置化字典表 `TB_SaleChannel`（C-01），二级结构如下。**

```text
线上
  ├─ 美团
  ├─ 抖音
  ├─ 大众
  ├─ 拼团
  ├─ 联营
  └─ 商场活动
门店
  ├─ 线下体验
  ├─ 微信小程序
  ├─ 支付宝
  └─ 银行卡付款
```

- 开单强制选**叶子渠道**；写入单据/账户 `Channel`（编码或名称与字典一致，实现时锁定一种）。  
- **销售渠道 ≠ 支付方式**：即使渠道名为「支付宝/银行卡付款」，实收仍记 `TB_PayMethod` + `TB_SaleBillPay`。  
- 禁止在 Java 硬编码渠道列表；允许后续总部增删改/停用。  
- 旧表 `TB_Channel` 仍表示渠道商/介绍人，不与本字典混用。

## CONF-012 销售欠尾款与可用余额

**已确认（2026-09-16）：**

- 允许欠尾款：`PayAmount + ArrearAmount = TotalAmount`。  
- **付多少本金录多少可用**：账户 `Balance`（本金可用）= 实付本金部分；`ArrearAmount`=欠款；面值字段保留成交面额。  
- **赠金不自动入账**：赠金金额/时机由前端显式传入；未传则赠金余额为 0（不做按比例自动赠送策略）。  
- 欠款未清不影响已入账可用余额的耗用。  
- 提供最小**平账/补尾款** API：减少 Arrear、增加 Balance，并写审计过程。
