## 1. Q1 销售退粒度（A）

### 口径

- 以销售单下的**各权益账户**为退款单元（项目/产品/次卡/时效/储值/套餐母户）。  
- **次卡 / 项目次数类**：`退款金额 = UnitPriceSnapshot（或账户单价快照）× Balance（剩余）`；已用次数不退、执行时不恢复已用。  
- **时效卡**：按账户剩余绩效次数 × 入账单价快照（字段以实库为准，禁止用当前 `TB_Project.Price`）。  
- 整单申请金额 = 各可退账户金额之和（服务端汇总）。  
- 前端若传 `items/amount`：**忽略或仅作展示校验**，最终以服务端为准。

### 现码冲突

- `countConsumedSaleAssets>0` 整单拒绝 → **删除该门槛**，改为按账户剩量计价。  
- 行金额复制 `TotalAmount`/`CardTimes` 全额 → 改为剩量×快照。

### 执行时

- 对纳入退款的账户：停用 + Balance/次数清零（或按退尽规则）；已用历史保留。  
- 源销售单：当本单关联可退账户均已退尽/停用后，标 `已退款`（若 V1 仅支持「一次申请覆盖整单可退账户」，则执行后整单 REFUNDED）。

**V1 简化（写入 CONF）：** 一张销售退款申请覆盖该销售单下**全部仍 Active 且有剩余**的账户；不支持勾选部分账户。金额仍按各账户剩量分别计算后加总。

## 2. Q2 审批与执行二段（A）

```text
create → ApprovalStatus=0 待审批
approve(true) → 1 已审批 + Process
approve(false) → 9 已驳回 + Process（可再开新单）
execute → 仅 status=1；冲销后 → 2 已执行 + Process
```

- 未审批 / 已驳回 / 已执行：禁止 execute。  
- 已执行：禁止再次 execute（防重复退款）。

## 3. Q3 耗卡取消 vs 耗卡退款

| 场景 | 路径 |
|---|---|
| BillDate 本月操作失误 | `treat cancel`（CONF-019，不审批） |
| 隔月、需财务退款出纳、客诉退费 | `TREAT` 退款（本模块，必审批） |
| TreatBill 已取消 | **禁止** create/execute TREAT 退 |
| TREAT 退已执行 | 源消耗单标记已退款（或等价态）；**禁止**再 cancel |

互斥检查：CancelProcess 存在或 BillStatus=已取消 → 拒退；退款已执行 → cancel 侧（若触及）应已由耗卡模块或本模块状态挡住。

## 5. Q5 储值销售退（A′ 纠偏）

### 00 强制

```text
赠金：不能退款
```

### 锁定

| 项 | 值 |
|---|---|
| 可退条件 | 本金余额 = 开户本金面值（未动本金）；即「本金未耗」 |
| 退款金额 | **剩余本金**（或开户实收中归属本金部分，V1=账户 `Balance`） |
| 赠金 | **不退现金**；执行时赠金余额清零并停用账户 |
| 已耗本金 | 该储值账户不可纳入本张销售退（或整单仍可退其他账户，该账户跳过并在明细标注不可退） |

若销售单仅含已部分消耗的储值且无其他可退账户 → 申请失败（无可退金额）。

## 7. Q7 退款支付（A）
