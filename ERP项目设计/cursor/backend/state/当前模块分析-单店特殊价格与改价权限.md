## 1. 模块目标

两个相关但不同的能力一并落地（指导书明确区分）：

1. **单店特殊价格**：申请→审批→生效（写 Adjustment）；报价 `priceSource=SPECIAL_STORE`  
2. **临时改价权限**：配置化规则 + 校验服务；增强 `allowAdjust`/`minPrice`；**不落销售单**

## 2. 业务范围摘要

**做：** C-06 申请流、审批写 `TB_ProjectPriceAdjustment`、C-07 规则、ModifyPriceEntity 维护、`PriceChangeService`、报价覆盖与改价试算 API。  

**不做：** 销售改价落库/快照、卡类特价与改价、多级审批引擎、改价二次审批流转、CONF-001 开单瀑布列表。

## 3. 与已确认规则对齐

| 规则 | 本模块方式 |
|---|---|
| CONF-009 | 仍选渠道；特价/活动为**渠道内覆盖** |
| CONF-001 | 特价须审批；临时改价受门店×项目×渠道×职务×金额约束 |
| 00 数据库第一 | Adjustment/ModifyPrice **优先复用**；C-06/C-07 须 **08→确认→执行** |
| 金额 | BigDecimal；禁止 double |

## 4. 已锁定约定（开发不得擅自改）

| # | 约定 |
|---|---|
| 1 | 同渠道覆盖序：`SPECIAL_STORE` > `ACTIVITY` > 门店/区域/总部渠道价 > 基价 |
| 2 | Adjustment 无渠道维 → V1 该店该项目**各叶子渠道同显特价** |
| 3 | 取消特价 = **删除** Adjustment 行（旧表无 Active） |
| 4 | V1 货品范围：**PROJECT** |
| 5 | 临时改价：**只降不升**；原因必填 |
| 6 | 多条 C-07 命中 → 取算出的 **最低价最严（最高 minPrice）** |
| 7 | C-07.`NeedApprove` V1 **存但不驱动流程** |
| 8 | 审批 V1 单级：`special-price:approve` |
