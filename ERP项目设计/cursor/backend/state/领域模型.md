## 0. 建模约定

| 概念 | 本项目约定 |
|---|---|
| 聚合根 | 事务一致性边界入口；外部只通过聚合根改内部 |
| 值对象 | 无独立生命周期（Money、Ratio、DateRange、PermissionCode…） |
| DO | 基础设施表映射，**不等于**领域实体 |
| 领域服务 | 跨实体无自然归属的纯规则（如价格解析） |
| 应用服务 | 用例编排、事务、权限、调用仓储/领域服务 |
| 仓储 | 聚合持久化端口；实现落 Mapper/旧表 |
| 领域事件 | 完成态事实，驱动权益/业绩/库存侧效应（可用同步先落地） |

金额一律 `BigDecimal`。禁止用名称/价格推断渠道或卡类型。

## 1. 总关系：销售 → 卡 → 耗卡 → 退款 → 提成

```text
Project / CardDefinition / Product   （可售定义）
        │
        ▼  PriceResolutionService（按门店+渠道+时间解析价）
SaleOrder(SaleBill)  ──Payment──►  支付完成
        │
        ├─► CustomerCardAccount*（发卡/充值入账，快照售价与退款价值）
        ├─► SalePerformance / SaleCommission 快照
        └─►（可选）库存出库

CustomerCardAccount*
        │
        ▼  TreatOrder(TreatBill)  扣减权益（护理师选储值本金/赠金等）
        ├─► TreatPerformance / TreatCommission 快照
        └─►（可选）ServiceRecord / 客流

SaleOrder / TreatOrder / Account
        │
        ▼  SaleRefund / TreatRefund
        ├─► 按销售时卡项价值 / 本金赠金规则冲回
        └─► 冲销对应业绩/提成（按规则）

关键不变量：
- 销售事件 ≠ 耗卡事件（团购即时消耗 = 两个事件同额，不是营业额翻倍）
- 历史单据快照不被主数据改价污染
- 提成规则变更不影响已落库快照
```

## 2. 价格领域（特别分析）+ PriceResolutionService

### 2.1 领域目标

在开单瞬间，为「某门店 + 某可售对象 + 某销售渠道 + 当前时间」算出**合法成交价候选**，并判定改价权限；**后端必须重算，不信任前端提交价**。

### 2.2 核心实体 / 值对象

| 类型 | 名称 | 说明 |
|---|---|---|
| 实体 | `PriceArea` | 价格区域（门店归属） |
| 实体 | `BasePrice` | 总部/区域标准价（按 Project/Product/CardDefinition） |
| 实体 | `ActivityPrice` | 统一活动价（含生效期、渠道、门店范围） |
| 实体 | `SpecialStorePrice` | 已审批单店特殊价 |
| 实体 | `PriceChangePermission` | 角色/员工改价权限（可否改、下限） |
| 值对象 | `Money` | 金额 |
| 值对象 | `PriceQuote` | 解析结果（见下） |
| 值对象 | `SaleChannelId` | 渠道标识（普通/美团/团购…）**显式字段** |

### 2.3 聚合

- **聚合根候选**：`SpecialStorePriceApply`（审批单）→ 通过后生成 `SpecialStorePrice`  
- `Activity` 聚合：活动头 + 活动价明细  
- 报价本身是**领域服务纯函数结果**，不单独持久为聚合（写入订单明细快照）

### 2.4 价格优先级（来自总规则 §10；若设计更新以已确认文档为准）

```text
1. 已审批的单店特殊配置 SpecialStorePrice
2. 统一活动价格 ActivityPrice（匹配渠道/门店/时间）
3. 区域标准价格 BasePrice@PriceArea
4. 总部基础价格 BasePrice@HQ
```

命中即停；须记录 `priceSource` + `priceRuleId` / `activityId`。

### 2.5 PriceResolutionService（领域服务）

**输入**

```text
storeId
itemType          // PROJECT | PRODUCT | SAVING_CARD | PACKAGE_CARD | GENERAL_CARD | TIME_CARD
itemId            // projectId / productId / cardDefinitionId
saleChannelId
currentTime
operatorRoleIds   // 可选，用于改价权限
```

**输出 `PriceQuote`**

```text
finalPrice          // 系统算出的标准成交价（改价前）
standardPrice       // 总部或区域标准价（展示/快照）
priceSource         // SPECIAL_STORE | ACTIVITY | AREA | HQ
priceRuleId         // 可空
activityId          // 可空
allowAdjust         // 是否允许人工改价
minPrice            // 改价下限（无权限则为 finalPrice）
adjustRuleId        // 改价规则引用
currency            // 默认 CNY
```

**规则**

1. 找不到可售/未上架 → 领域异常 `GOODS_NOT_SELLABLE`  
2. 渠道必须显式传入，禁止从项目名/价格猜  
3. 前端 `salePrice` 若 ≠ `finalPrice`：校验 `allowAdjust` 且 `salePrice >= minPrice`，否则拒绝  
4. 写入销售明细时快照：`standardPriceSnapshot, salePriceSnapshot, priceSource, priceRuleId, activityId, saleChannelId`

### 2.6 Application / Repository / API / 异常

| 层 | 内容 |
|---|---|
| Application | `PriceQueryApplicationService.quote(...)`；管理端活动/特价/改价权限配置用例 |
| Repository | `PriceRuleRepository`, `ActivityRepository`, `SpecialStorePriceRepository`, `StorePriceAreaRepository` |
| API | `GET /api/v1/prices/quote`；管理端 CRUD（后续 E04） |
| 异常 | `PRICE_NOT_FOUND`, `PRICE_ADJUST_FORBIDDEN`, `PRICE_BELOW_MIN`, `CHANNEL_REQUIRED` |

### 2.7 【业务歧义】待确认

| 问题 | 已知 | 方案 | 推荐 |
|---|---|---|---|
| 旧库价格落在哪些表（Project 字段 vs PriceAdjustment vs SaleEntity） | 有 `TB_ProjectPriceAdjustment`、`TB_ProductModifyPriceEntity`、`TB_*SaleEntity` 等 | A 先做映射再实现服务 / B 先按总规则抽象再映射 | **A**：04 数据库映射阶段锁表字段后再编码 |

## 3. 分领域模型卡（统一 15 项压缩格式）

### 3.1 项目 Project

1. **目标**：可售护理/服务标准项目，一项目多渠道，不按渠道拆项目  
2. **实体**：Project, ProjectCategory, ProjectConsumableTemplate  
3. **属性**：id, name, categoryId, active, sellable, consumableTemplateId…  
4. **状态**：启用/停用；可售/不可售  
5. **变化**：启用↔停用；不影响历史订单名称价（靠快照）  
6. **聚合根**：Project  
7. **边界**：含分类关联、耗材模板引用；不含订单与账户  
8. **规则**：PRO-004/006 基价与成交价分离；渠道不是项目副本  
9. **Domain**：ProjectSellabilityPolicy  
10. **App**：ProjectApplicationService（CRUD/上架门店）  
11. **Repo**：ProjectRepository → `TB_Project*`  
12. **事件**：ProjectDeactivated  
13. **DB**：`TB_Project`, `TB_ProjectCategory`, `TB_ProjectSaleEntity`, …  
14. **API**：`/api/v1/projects`  
15. **异常**：`GOODS_NOT_FOUND`, `GOODS_NOT_SELLABLE`

### 3.2 销售渠道 SaleChannel

1. 标识成交路径（普通/美团/团购…）  
2. SaleChannel（或字典+门店开通）  
3. id, code, name, active  
4. 启用/停用  
5. 停用后不可新开单使用该渠道  
6. 聚合根：SaleChannel（或 StoreSaleChannel 开通关系）  
7. 不含价格明细（价格在 Price 域）  
8. 禁止名称推断；开单必填 channelId  
9. ChannelEligibilityService  
10. SaleChannelApplicationService  
11. SaleChannelRepository  
12. —  
13. 待映射旧 Channel / 相关 SaleChannel* 表  
14. `/api/v1/sale-channels`  
15. `CHANNEL_REQUIRED`, `CHANNEL_DISABLED`

### 3.3 门店 Store / 区域 Region

1. 经营单元与组织范围  
2. OrganizationNode；Store 为 IsStore=true 的节点；PriceArea 可挂门店  
3. id, name, parentId, isStore, priceAreaId, active  
4. 启用/停用  
5. 停用不可切店开单  
6. 聚合根：OrganizationNode（树）  
7. 员工归属、跨店关系在员工侧；权限范围在 Access 侧  
8. 组织范围勾选上级含下级门店  
9. OrgTreeExpandService（已有 OrgDataScopeService 思想）  
10. OrganizationApplicationService  
11. OrganizationRepository → `TK_Entity`  
12. —  
13. `TK_Entity`  
14. `/api/v1/organizations`, `/api/v1/stores`  
15. `STORE_FORBIDDEN`

### 3.4 活动 Activity / 特殊价格 SpecialStorePrice / 价格权限

见 §2。管理端审批流：`SpecialPriceApply` 状态 草稿→审批中→通过/驳回→生成 SpecialStorePrice。

### 3.5 会员 Customer（摘要）

1. 客户主档与门店关系、标签、来源、护理师  
2. Customer, CustomerStoreRelation, Tag, Source, ServicerBinding

8. 客户≠权益账户  
9～15. 已有 Customer* 服务与 `TB_Customer*`；补权限注解

### 3.6 储值卡 SavingCard

1. 定义可售储值产品；账户持本金/赠金  
2. SavingCardDefinition；SavingCardAccount；SavingCardTransaction  
3. 定义：售价, principal, bonus, validityYears…；账户：principalBalance, bonusBalance, expireAt, sourceSaleBillId, openStoreId, status

5. 销售完成→开户；耗卡→扣款；延期；过期  
6. **聚合根：SavingCardAccount**（余额一致性）；Definition 独立聚合  
7. 流水在账户聚合内  
8. CAR-001～010：本金跨店、赠金不跨店不退、护理师选扣款来源、禁止直接改余额、默认 3 年  
9. SavingDeductionService（选择本金/赠金校验门店）

11. SavingCardDefinitionRepository, SavingCardAccountRepository → `TB_SavingCard`, `TB_SavingCardAccount`

13. 同上表 + 流水表（若有）  
14. 定义管理 API + 账户查询  
15. `ASSET_INSUFFICIENT`, `BONUS_CROSS_STORE_FORBIDDEN`, `BONUS_REFUND_FORBIDDEN`

### 3.7 次卡 GeneralCard（通用次卡）

1. 按次权益  
2. GeneralCardDefinition / GeneralCardAccount  
3. totalTimes, remainTimes, expireAt, transferable…  
4. 正常/冻结/用尽/过期  
5. 销售开户；耗卡减次；转让（审批）；延期  
6. 聚合根：GeneralCardAccount  
7. 转让申请可作独立聚合  
8. CAR-040～046 跨店、延期、转让审批、明细记录；退款恢复数量【歧义待锁定】

12. GeneralCardConsumed, GeneralCardTransferred  
13～15. 同模式；`ASSET_INSUFFICIENT`

### 3.8 时效卡 TimeCard

1. 有效期+周期规则，不能只看总次数  
2. TimeCardDefinition / TimeCardAccount  
3. expireAt, periodRule, performanceTimes vs usageTimes（旧事实）  
4. 正常/过期/冻结  
5. 销售开户；按规则耗用；延期  
6. 聚合根：TimeCardAccount  
7. 周期规则在定义或账户快照  
8. CAR-060～062  
9. TimeCardConsumeService

### 3.9 套餐卡 PackageCard

1. 组合权益模板；售出后内容不可替换  
2. PackageCardDefinition + 子项（项目/产品/储值/次卡/时效）；PackageCardAccount + 子账户项（含退款价值快照）

10. PackageCardApplicationService

12. PackageOpened, PackageItemConsumed, PackageItemRefunded  
13～15. 退款价值缺失则禁止退

### 3.10 销售 Sale

1. 客户购买行为；与支付分离  
2. SaleOrder(SaleBill), SaleOrderItem*, SaleHandler, Payment  
3. 金额字段分离：标准价快照、成交价、优惠、应收、已付、欠款、储值抵扣…  
4. 建议：草稿→待支付→支付中→已支付→已完成；待支付→已关闭；已完成→部分退款/已退款  
5. 未支付可取消；已支付不可删，走退款  
6. **聚合根：SaleOrder**  
7. 含明细、处理人、支付；发卡在领域事件后由权益域开户（同事务可编排）

13. 见扫描表族  
14. `/api/v1/sales/orders`

**【业务歧义】** 旧 `BillStatus` 与上述状态枚举映射未在规则库锁死 → 04/开发前确认。

### 3.11 耗卡 Treat

1. 使用权益形成消耗事件；不产生新的“销售营业额”  
2. TreatOrder, TreatOrderItem, TreatSource（账户来源）

4. 待完成→已完成；取消流程

6. **聚合根：TreatOrder**  
7. 不修改销售单价；只改账户与耗卡事实

9. SaleCommissionCalculator, TreatCommissionCalculator（超额累进）  
10. CommissionApplicationService / 结算  
11. → `TB_*Performance*`, `*Commission*`（04 映射细表）  
12. CommissionCalculated, CommissionSettled  
13～15. 无方案则记 0 或拒绝结算【待确认】
