# 第十六部分



# 最重要的 Cursor 使用纪律

以后你和 Cursor 聊天，尽量不要说：

```text
帮我把这个功能做一下。
```

而要说：

```text
执行05-Cursor模块开发Prompt。

当前模块：
价格中心。

严格按照00～04已经确认的设计开发。

完成以后停止。
```

**如果发现问题：**

```text
执行11-Cursor问题处理Prompt。

问题：
……
```

**如果想检查代码：**

```text
执行06-Cursor代码审查Prompt。
```

**如果怀疑业务错了：**

```text
执行07-Cursor业务规则审查Prompt。
```

**如果 Cursor 修改了数据库：**

```text
执行08-Cursor数据库变更审查Prompt。
```

**如果要测试：**

```text
执行09-Cursor测试Prompt。
```

**如果准备验收：**

```text
执行10-Cursor模块验收Prompt。
```

**如果要进入下一块：**

```text
执行12-Cursor下一模块启动Prompt。

下一模块：
……
```

# 第十七部分



# Cursor 不允许做的事情

以下行为视为严重违规：

```text
1. 自己改变业务规则
2. 自己重新设计数据库
3. 为了方便新增大量表
4. 删除旧字段
5. 修改旧字段含义
6. 通过价格判断渠道
7. 通过名称判断渠道
8. 通过价格判断卡类型
9. 用当前价格重新计算历史订单
10. 用当前价格重新计算历史卡项
11. 前端决定最终价格
12. Controller直接操作Mapper
13. 使用double处理金额
14. 不加事务修改余额
15. 不考虑并发扣款
16. 重复退款
17. 重复耗卡
18. 修改已经完成的历史提成
19. 绕过权限
20. 未完成当前模块就自动进入下一模块
```

一旦出现：

```text
STOP
```

然后进入：

```text
11-Cursor问题处理Prompt
```

# 第十八部分



# 最终目标

最终 Cursor 应该形成这样的研发闭环：

```text
                    ┌──────────────┐
                    │ 业务设计文档 │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ 领域模型设计 │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ 数据库映射   │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ 模块开发     │
                    └──────┬───────┘
                           ↓
                 ┌────────────────────┐
                 │                    │
                 ↓                    ↓
           代码审查               业务审查
                 │                    │
                 └─────────┬──────────┘
                           ↓
                    ┌──────────────┐
                    │ 数据库审查   │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ 测试         │
                    └──────┬───────┘
                           ↓
                    ┌──────────────┐
                    │ 模块验收     │
                    └──────┬───────┘
                           ↓
                       PASS？
                      /     \
                    NO       YES
                    ↓         ↓
                  问题处理   下一模块
                    │         │
                    └────←────┘
```

这套机制的目的不是让 Cursor “写更多代码”。

而是让 Cursor：

**少猜、少乱改、少重构数据库、少制造隐患，并且让每一个业务模块都能被验收。**

# 最终开发状态文件建议

为了让 Cursor 长期保持上下文，建议项目再增加：

### `当前研发状态.md`

以后你在 Cursor 里甚至可以非常简单：

```text
读取 design/cursor/00-Cursor开发总规则.md。

当前按照研发流程继续。

当前模块：
耗卡中心。

先执行分析，不要写代码。
```

分析确认以后：

```text
执行05-Cursor模块开发Prompt。

模块：
耗卡中心。

严格按照已经确认的领域模型和数据库映射开发。

完成后停止。
```

开发完成：

```text
执行06、07、08、09、10。

依次完成：

代码审查
业务规则审查
数据库审查
测试
最终验收。

任何P0/P1问题立即停止。
```

验收通过：

```text
执行12-Cursor下一模块启动Prompt。

下一模块：
统一活动。
```

如此循环。
